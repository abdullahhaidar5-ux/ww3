# Perf 1103 — "massive columns" profile (branch `orch/perf-1103`)

**Tool:** `orch/columns.mjs` (existing 8-player late-game profiler) extended with
`--simprof` (sim-only CPU profile + `separate()` micro-timing), `--syncprof` (CPU profile of syncScene+fxUpdate, no GPU),
`--glcount` (WebGL calls and upload sizes per frame). Add `--phone` for 390x844, dpr 3, 4x CPU slowdown (Low-like).
Example: `node orch/columns.mjs --phone --simprof --syncprof --minutes 4`.

**Where a late-game frame goes** (8 players, Fulda, ~350-400 units, SwiftShader so GPU numbers are relative only)

| part | desktop ms | phone-like (4x CPU) ms |
|---|---|---|
| sim step (60 Hz) | 3.3 | 12-16 |
| syncScene (units -> 3D) | 3.8 | 14.5 |
| fxUpdate | 2.5 | 8.2 |
| draw calls / triangles / shadow casters | ~600-1200 / 4.4-6.7M / ~2200 | similar, fewer tris on Low |

Sim top costs: `separate` (push-apart) ~19%, path search ~11%, main loop ~12%, unit update/step ~14%, `nearby` 6%.
Render-prep is a flat profile (matrix updates, no single hotspot). GPU time can't be measured headless: the real
limit on a phone is probably draw calls + triangles + shadow casters, which only a real iPhone can show.
GL: ~130 tiny bone-texture uploads per frame (20x20 / 16x16) and rare big canvas uploads (minimap 672x462 etc.); no
per-frame large upload found.

**Fixed:** `separate()` (units pushing each other apart) now uses flat arrays instead of a Map of lists, and sqrt instead of
hypot. Same pairs in the same order, play unchanged.

| | before | after |
|---|---|---|
| separate() desktop | 0.53 ms | 0.31-0.33 ms (-38%) |
| separate() phone-like | 1.80 ms | 1.38 ms (-23%) |
| whole sim step | ~3.3 | ~3.3-3.5 (noise bigger than gain) |

Honest result: a small gain. Sim is not the main cost; the next real wins are in rendering (merge vehicle parts,
fewer shadow casters/triangles, cheaper far units) — owned by the visuals squad and needing a real-phone measurement first.
Sim change => servers-live PR needed (see HISTORY).
